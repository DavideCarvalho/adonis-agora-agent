Developer tools over MCP. `mcp_provider` now serves `/mcp/agora`: one MCP endpoint where every installed `@adonis-agora` lib with a console registers read tools (actions opt-in), each gated by that console's own `authorize`, so `tools/list` only shows the libs the caller may use. Nothing to configure: `claude mcp add --transport http agora http://localhost:3333/mcp/agora`. With `@adonis-agora/authkit-server` installed, MCP clients sign in through the standard OAuth flow and the account reaches each console's `authorize` like a browser session (Poppy tokens need the `agora:dev` scope); console tokens (`authorizeByToken`) work as a bearer. Opt-outs in `config/mcp.ts`: `devTools: false | { path, exclude, actions, middleware }`. The agent registers its own seven governance read tools (`agent_list_runs`, `agent_get_run`, `agent_get_spend`, …). Libs register through the `'agora.devTools'` hub (contract in `@adonis-agora/agent/dev-tools`, copied structurally, no import). Also new: `anyAuthorize(...)` to allow a console when any of several checks allows it.
