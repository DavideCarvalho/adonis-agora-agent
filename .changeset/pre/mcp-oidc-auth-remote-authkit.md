MCP with authkit on another server. New `oidcAuth({ issuer, resource?, … })` for product MCP endpoints: verifies JWT access tokens against the issuer's JWKS (found by discovery; same core as the dev hub's `jwtAuth`), advertises the issuer in the RFC 9728 metadata and challenges with `resource_metadata`, needs no authkit-server in the app. `toActor` receives `{ subject, claims, scopes, roles, clientId, actor, personalAgent }`; the impersonator (`act` claim) is also on `authInfo.extra.act`. `jwtAuth` and `oidcAuth` now put a verified user token on the request as an authkit identity (`ctx.authkit`, via `@adonis-agora/authkit-client`'s `identityFromClaims` / `bindAuthkitIdentity`, a new optional peer `>=1.0.0-rc.7`), so `getAuthkit(ctx)` / `authkitDashboardAuthorize()` see remote callers; `authkit: false` turns it off. A token without `email` is bound to `ctx.authkit` only (the app's `resolveUser` is not run). The in-process authkit bridge uses the same helper. Dev tools audit an impersonation token as the real actor (`caller.id = user:<act.sub>`, `onBehalfOf: user:<sub>`); `DevToolsPrincipal.actor` is new. `McpVerifyContext` gains `ctx`; `McpOAuthMetadata.authorizationEndpoint`/`tokenEndpoint` are now optional.
