Text channels: bursts of messages become one turn, and durable jobs run their phases as dispatched steps.

- **`coalesce` (opt-in).** `channels.handle(adapter, { coalesce: { quietMs, maxWaitMs?, maxMessages?, when? } })` groups the messages a person sends in a row — "oi" / "tudo bem?" / "queria saber X", or ten PDFs — into ONE turn once the conversation has been quiet for `quietMs` (at most `maxWaitMs`, default 30 s; at most `maxMessages`, default 20): texts joined in order, every file attached, each message's files prepared and refused as if alone. Button presses, text decisions and answers to a question are never grouped and end a burst; messages that arrive while a grouped turn runs go to the next one. Under a durable engine the wait is the engine's durable sleep (resumable on any instance); inline, a timer. Every message keeps its own job and its own dedupe; the first to run leads and claims the others in the channel store, so nothing is answered twice or dropped across retries, recoveries and redelivered webhooks. Hooks see the burst through new optional fields: `ChannelHookContext.coalesced`, `ChannelInbound.parts`, and `coalesced` / `attachments` / `queueWaitMs` on `onTurnStarted` and `onTurnEnded` (set only with `coalesce` on). Off by default: nothing changes for a channel without it.
- **Dispatched phases.** The `agora.channel.job` / `agora.channel.timer` workflows are now at version `2`: each phase is a dispatched step (`agora.channel.prepare`, `agora.channel.act`, `agora.channel.read`, `agora.channel.gather`, `agora.channel.timeout`) served on the durable engine's transport by every process that created the channel's handler, so any process runs a phase and any process continues the job. Each carries a liveness timeout (a lost step is dispatched once more, then fails the job instead of hanging). The agent's engine is served on its container transport automatically; an engine passed as `durable: engine` takes `durableSteps: transport` (or an engine `handleStep`); `durableSteps: false` keeps the phases as local steps. Version `1` stays registered, so runs in flight during the upgrade finish on their old path. `ChannelWorkflowEngine` gains optional `handleStep`, `ChannelWorkflowCtx` optional `step` / `sleepUntil` / `sleep`; `ChannelStepServer`, `ChannelStepLog`, `ChannelCoalesceOptions` and `ChannelInboundPart` are exported.
