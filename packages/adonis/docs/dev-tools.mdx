import { Callout } from 'fumadocs-ui/components/callout';

With `@adonis-agora/agent/mcp_provider` in `adonisrc.ts`, your app serves `/mcp/agora`: an MCP
endpoint where every installed Agora lib that has a console registers its developer tools. You
configure nothing and list nothing. Ask your coding agent "why did run 42 fail?" or "what did the
agent spend today?" and it reads the same data your consoles show.

## Connect a client

```sh
claude mcp add --transport http agora http://localhost:3333/mcp/agora
```

Cursor, Claude Desktop and any other MCP client take the same URL (Streamable HTTP).

How the client gets in depends on how your consoles are protected:

- **Consoles with no `authorize`** (the default outside production): the tools are open locally, like
  the consoles.
- **`authorizeByToken`**: send the console token as a header.

  ```sh
  claude mcp add --transport http agora http://localhost:3333/mcp/agora \
    --header "Authorization: Bearer $CONSOLE_TOKEN"
  ```

- **Your app's own `@adonisjs/auth` access tokens**: each developer sends a personal token instead
  of a shared one. See [Without authkit](#without-authkit).
- **`@adonis-agora/authkit-server` in the app**: the client opens the login in your browser (standard
  MCP OAuth), and the account you sign in with reaches each console's `authorize` exactly like your
  browser session does. `authkitDashboardAuthorize()`, `authorizeByRoles({ roles: ['ADMIN'] })` or
  `(ctx) => ctx.auth.user?.isAdmin` work over MCP unchanged.

<Callout title="MCP sign-in turns on by itself">
The OAuth login uses authkit's MCP client login. It is on whenever an MCP resource is registered with
authkit, and the dev endpoint registers itself as one, so there is nothing to set. Only
`mcpClients: false` in `config/authkit.ts`, or the admin console's MCP clients switch, turns it off.
The dev endpoint is a protected resource of its own, so a token issued for your product MCP endpoint
is refused here, and the other way round.
</Callout>

### Without authkit

Without authkit, give each developer their own token with the `@adonisjs/auth` access tokens guard
and check it in each console's `authorize`. Add an `api` guard next to your session guard:

```ts title="config/auth.ts"
import { defineConfig } from '@adonisjs/auth'
import { sessionGuard, sessionUserProvider } from '@adonisjs/auth/session'
import { tokensGuard, tokensUserProvider } from '@adonisjs/auth/access_tokens'

export default defineConfig({
  default: 'web',
  guards: {
    web: sessionGuard({
      useRememberMeTokens: false,
      provider: sessionUserProvider({ model: () => import('#models/user') }),
    }),
    api: tokensGuard({
      provider: tokensUserProvider({ tokens: 'accessTokens', model: () => import('#models/user') }),
    }),
  },
})
```

```ts title="app/models/user.ts"
import { DbAccessTokensProvider } from '@adonisjs/auth/access_tokens'

export default class User extends compose(BaseModel, AuthFinder) {
  // …
  static accessTokens = DbAccessTokensProvider.forModel(User)
}
```

Then one `authorize` serves both the browser (session) and MCP clients (token). `checkUsing` never
throws; it tries each guard in turn and sets `ctx.auth.user`:

```ts title="app/consoles/is_admin.ts"
import type { HttpContext } from '@adonisjs/core/http'

export async function isAdmin(ctx: HttpContext) {
  await ctx.auth.checkUsing(['web', 'api'])
  return ctx.auth.user?.isAdmin === true
}
```

Use it as every console's `authorize` (`dashboard.authorize` here, the same option in durable,
telescope, payments, media and flags) and as `devTools.authorize` for the libs without a console.
To accept tokens only, check the guard directly:
`async (ctx) => { await ctx.auth.use('api').check(); return ctx.auth.use('api').user?.isAdmin === true }`.

Each developer creates a token once, for example from a command or a settings page, and gets its
value back only at that moment:

```ts
const token = await User.accessTokens.create(user)
token.value!.release() // oat_…
```

and adds it to the client:

```sh
claude mcp add --transport http agora http://localhost:3333/mcp/agora \
  --header "Authorization: Bearer <token>"
```

Put the check in `authorize`, not in `devTools.middleware`: every lib with a console decides with its
own `authorize`, and `devTools.middleware` is for route concerns such as rate limiting.

Browser login (MCP OAuth, where the client opens a sign-in page) needs authkit's MCP client login.
Without authkit, MCP clients use a header token.

## What you see

`tools/list` holds the tools of the libs whose console lets you in, and nothing else. If durable and
telescope allow you but payments does not, you see durable and telescope tools only.

Tool names start with their lib: `durable_list_runs`, `telescope_get_entry`, `agent_get_spend`. List
tools take `limit` (default 20, at most 100) and return `{ items, next }`; pass `next` back to page.
Results are capped at 48 KB, long blobs are cut with `…(truncated, N bytes)`, and values under keys
that name a secret (`token`, `password`, `secret`, `cookie`, `authorization`, `api_key`) are
replaced with `[redacted]`.

The agent registers its governance console, read-only:

| Tool | What it returns |
| --- | --- |
| `agent_list_runs` | Runs, newest first. Filters: `agent`, `status`, `actor`, `from`/`to`, `cursor`. |
| `agent_get_run` | One run's trace. Messages only with `includeMessages: true`, 2 KB each. |
| `agent_get_spend` | Tokens and cost over a range of days, `by` model, actor or feature. |
| `agent_get_tool_stats` | Calls, failures, rejections and latency per tool. |
| `agent_get_reliability` | Success, failure and cancel rates. |
| `agent_list_pending_approvals` | Tool calls waiting for a human approval. |
| `agent_list_recent_tool_calls` | The latest tool calls of every agent. |

Each lib's docs list its own tools.

## Who gets in

Every request is checked again, per lib, with the `authorize` of that lib's console — the same
function its console routes run. A call to a tool of a lib that refuses you answers like that
console would: `401 { "error": "unauthenticated" }` or `403 { "error": "forbidden" }`.

A console that wants a browser session (`{ redirectTo: '/login' }`) refuses an MCP client that has
none. Install authkit for the sign-in above, or accept a token as well with `anyAuthorize`:

```ts title="config/agent.ts"
import env from '#start/env'
import { anyAuthorize, authorizeByToken, defineConfig } from '@adonis-agora/agent'

export default defineConfig({
  dashboard: {
    authorize: anyAuthorize(
      authorizeByToken({ token: env.get('CONSOLE_TOKEN') }),
      (ctx) => ctx.auth.user?.isAdmin === true,
    ),
  },
})
```

### Libs without a console

Resilience, authz, diagnostics and filter have no console, so they have no `authorize` of their own.
Their tools are gated by `devTools.authorize`, which takes the same forms as any console's
`authorize`:

```ts title="config/mcp.ts"
import env from '#start/env'
import { authorizeByToken } from '@adonis-agora/agent'
import { defineMcpConfig } from '@adonis-agora/agent/mcp'

export default defineMcpConfig({
  name: 'Acme',
  version: '1.0.0',
  devTools: {
    authorize: authorizeByToken({ token: env.get('CONSOLE_TOKEN') }),
  },
})
```

Left out, those tools are open outside production and refused in production, and the app says so
once at boot. `devTools.authorize` never applies to a lib that has a console: durable, telescope,
payments, media, the agent and authkit keep their own.

A personal agent signed in through Poppy reaches the dev tools only when its user granted the
`agora:dev` scope.

## Actions

Tools that change data (retry, cancel, refund…) are hidden by default. `devTools.actions` decides
which ones each caller gets. An action it refuses is not listed in `tools/list` and cannot be
called. The lib's console `authorize` still runs first: `actions` only narrows what a lib already
lets the caller see.

Give each lib, or each tool, its own `authorize`. These take the same forms as a console's
`authorize` (a function, an authorizer class, a lazy import):

```ts title="config/mcp.ts"
import { authorizeByRoles } from '@adonis-agora/authz'
import { defineMcpConfig } from '@adonis-agora/agent/mcp'

export default defineMcpConfig({
  name: 'Acme',
  version: '1.0.0',
  devTools: {
    authorize: authorizeByRoles({ roles: ['ADMIN'] }),
    actions: {
      flags: authorizeByRoles({ roles: ['ADMIN'] }),
      flags_save_flag: authorizeByRoles({ roles: ['OWNER'] }),
      payments_refund_payment: () => false,
      durable: () => import('#policies/dev_tools_actions'),
    },
  },
})
```

- A tool-name key (`flags_save_flag`) wins over its lib's key (`flags`).
- An action that matches neither key is refused.
- An `authorize` that throws, or answers `{ redirectTo }`, refuses.
- Each `authorize` runs once per request, however many tools point at it.

For full control, pass a function. It is asked once per action tool, per request:

```ts title="config/mcp.ts"
devTools: {
  actions: async (ctx, { lib, tool, destructive, caller }) => {
    const user = ctx.auth.user
    if (!user) return false
    return destructive ? user.isOwner : user.isAdmin
  },
},
```

Anything but `true` (a `false`, a truthy non-boolean) or a throw refuses. A refused action is logged at
`debug` level only.

The shorthands still work: `'refuse'` (the default), `'execute'` (every action of every lib the
caller gets in), or a list of lib ids and tool names (`['durable', 'payments_refund_payment']`). Your
product endpoint's `actions: 'execute'` does not apply here.

## Opt-outs

All optional, in `config/mcp.ts`:

```ts title="config/mcp.ts"
export default defineMcpConfig({
  name: 'Acme',
  version: '1.0.0',
  // …your product endpoint…

  devTools: {
    path: 'mcp/agora', // the default
    exclude: ['payments', 'durable_get_run'], // lib ids or tool names
    actions: ['durable'], // see Actions above
    middleware: [() => import('#middleware/throttle_dev_tools')],
  },
})
```

- `devTools: false` turns the endpoint off.
- `authorize`: who may use the tools of libs without a console (see above).
- `actions`: which tools that change data each caller gets (see [Actions](#actions)).
- None of the product endpoint's settings (`auth`, `allowedTools`, `authorizer`, `middleware`,
  `publicUrl`) apply to the dev endpoint.

## CSRF

Shield's CSRF check rejects the client's `POST` unless the path is exempt. When it is not, the app
says so at boot. Add it to `config/shield.ts`:

```ts title="config/shield.ts"
csrf: {
  enabled: true,
  exceptRoutes: (ctx) => ctx.request.url().startsWith('/api/') || ctx.request.url() === '/mcp/agora',
},
```

## Registering a lib's tools

A lib (or your own app) registers tools from a provider's `boot()`. It needs no import from
`@adonis-agora/agent`: the contract is structural, so copy the types from
`@adonis-agora/agent/dev-tools` and this helper.

```ts title="providers/reports_provider.ts"
import type { ApplicationService } from '@adonisjs/core/types'
import ReportService from '#services/report_service'

async function registerDevTools(app: ApplicationService, lib: DevToolsLib) {
  if (!app.container.hasBinding('agora.devTools')) return false
  const hub = (await app.container.make('agora.devTools')) as Partial<DevToolsHub> | undefined
  if (hub?.version !== 1 || typeof hub.register !== 'function') return false
  hub.register(lib)
  return true
}

export default class ReportsProvider {
  constructor(protected app: ApplicationService) {}

  async boot() {
    await registerDevTools(this.app, {
      lib: 'reports',
      title: 'Reports',
      // The console's own resolved gate. Never throws.
      authorize: async (ctx) =>
        ctx.auth.user?.isAdmin ? { allowed: true } : { allowed: false, reason: 'forbidden' },
      tools: [
        {
          name: 'reports_list_failed',
          kind: 'read',
          description: 'Reports that failed to render, newest first. Returns { items, next }.',
          input: {
            type: 'object',
            properties: {
              limit: { type: 'integer', minimum: 1, maximum: 100 },
              page: { type: 'integer', minimum: 1 },
            },
          },
          async run(input, { ctx }) {
            const service = await ctx.containerResolver.make(ReportService)
            const page = Number(input.page ?? 1)
            const items = await service.failed({ page, limit: Number(input.limit ?? 20) })
            return { items, next: items.length > 0 ? page + 1 : null }
          },
        },
      ],
    })
  }
}
```

The rules:

- `lib` matches `/^[a-z][a-z0-9]*$/`, and each tool name is `<lib>_<verb>_<noun>` in snake_case.
  Reads use `list`, `get`, `count`, `search` or `explain`; actions use the console's own verb and set
  `kind: 'action'` (plus `destructive: true` for cancel, refund, revoke, delete).
- `input` is a JSON Schema subset: an object of `string` (with `enum`), `number`, `integer` (with
  `minimum`/`maximum`), `boolean` and arrays of strings. Unknown properties are rejected before
  `run` is called.
- `available()` hides a tool this deployment cannot run (say, refunds on a gateway without them). It
  is not access control: `authorize` is.
- Return what the console returns. Register nothing when the console is disabled.
- A lib with no console leaves `authorize` out, and registers only on a hub that gates it:
  `if (!lib.authorize && hub.supports?.('endpoint-authorize') !== true) return false`.
- `run` receives `{ ctx, caller, limits }`: `caller.id` (`token:…`, `user:…` or `dev-open`) is what to
  write in an audit trail.

Every call is logged (`info` for actions, `debug` for reads) with the tool, the caller and the
redacted arguments, and published as the `agent:devtools.call` diagnostics event.
