1.0 removes the options that 0.x kept only for older code. Your app compiles against 1.0 once each change below is applied. Nothing here touches your database: the agent tables, the published migration and runs already journaled by a durable worker all work as before.

## Install the release candidate

```bash
pnpm add @adonis-agora/agent@rc @adonis-agora/agent-dashboard@rc
```

Upgrade the other `@adonis-agora/*` packages you use to their 1.0 release candidates at the same time. The agent accepts both their 0.x and their 1.x releases.

## Node 24 or later

Both packages require Node 24 or later (`engines.node: ">=24"`), as AdonisJS 7 does. They are tested on Node 24 and 26.

## `ChatQueueService`: `personaFor` is removed

If you build a `ChatQueueService` yourself (the agent provider builds one for you), replace `personaFor` with `resolveTarget`. `resolveTarget` receives the whole queued message and returns the agent and persona it starts as.

Before:

```ts title="app/services/agent_queue.ts"
import { ChatQueueService } from '@adonis-agora/agent'

export const queue = new ChatQueueService(store, sink, {
  personaFor: (agentName) => personas.forAgent(agentName),
})
```

After:

```ts title="app/services/agent_queue.ts"
import { ChatQueueService } from '@adonis-agora/agent'

export const queue = new ChatQueueService(store, sink, {
  resolveTarget: async (message) => ({
    ...(message.agentName !== undefined ? { agentName: message.agentName } : {}),
    persona: personas.forAgent(message.agentName)?.id,
  }),
})
```

A queued message that already carries a persona still starts under it, and `resolveTarget` is not called for it.

## `streamTransports` is removed

`streamTransports` was a second name for `tokenSinks`. Import `tokenSinks` instead.

Before:

```ts title="config/agent.ts"
import { defineConfig, streamTransports } from '@adonis-agora/agent'

export default defineConfig({
  sink: streamTransports.redis({ connection: 'main' }),
})
```

After:

```ts title="config/agent.ts"
import { defineConfig, tokenSinks } from '@adonis-agora/agent'

export default defineConfig({
  sink: tokenSinks.redis({ connection: 'main' }),
})
```

## Dashboard: `window.__AGENT_DASHBOARD_BASE__` is no longer read

The console and `resolveApiBase()` from `@adonis-agora/agent-dashboard/client` read the agent's API base from the JSON data block the provider injects into the page, and otherwise derive it from the page URL. A page that embeds the console itself sets the base with that data block instead of the global.

Before:

```html title="resources/views/console.edge"
<script>window.__AGENT_DASHBOARD_BASE__ = '/api/agent'</script>
```

After:

```html title="resources/views/console.edge"
<script type="application/json" id="agent-dashboard-config">{"apiBase":"/api/agent"}</script>
```

A data block is never executed, so a Content-Security-Policy with `script-src 'nonce-…'` does not block it. If you build an `AgentClient` yourself, you can also pass `baseUrl`.

## Sandbox kit: the options from before 0.75 are no longer checked

`genuiSandboxKit()`, `genuiKitHook()`, `writeSandboxKitDocs()` and `defineSandbox()` used to throw when they received an option that 0.75 replaced. In 1.0 those options are simply not part of the types. TypeScript rejects them, and plain JavaScript ignores them. If your config still passes one, rename it:

| Before | After |
| --- | --- |
| `entry: 'kit.ts'` | `components: 'kit.ts'` |
| `include: 'components/ui/*.tsx'` | `components: 'components/ui/*.tsx'` |
| `css: 'resources/css/app.css'` | `styles: 'resources/css/app.css'` |
| `tailwind: true`, `tailwindCss: [...]` | `styles: '<your Tailwind stylesheet>'` (Tailwind is detected from it) |

Before:

```ts title="vite.config.ts"
genuiSandboxKit({
  include: 'inertia/components/ui/*.tsx',
  tailwind: true,
  tailwindCss: ['inertia/css/app.css'],
})
```

After:

```ts title="vite.config.ts"
genuiSandboxKit({
  components: 'inertia/components/ui/*.tsx',
  styles: 'inertia/css/app.css',
})
```

For a sandbox in your catalog, drop `tailwind` and keep `kit`:

```ts title="app/agent/catalog.ts"
// Before
defineSandbox({ kit: true, tailwind: true })

// After
defineSandbox({ kit: true })
```

## React: `ApprovalTarget` has only the `proposal` kind

The `ApprovalTarget` type that `approve` and `reject` accept from `@adonis-agora/agent/react` no longer includes `{ kind: 'legacy', toolCallId }`. Nothing read that kind. To approve a tool call, pass no target. To decide an action proposal, pass `{ kind: 'proposal', proposalId, threadId }`.

Before:

```tsx title="inertia/components/approval_buttons.tsx"
<button onClick={() => approve(part.toolCallId, undefined, { kind: 'legacy', toolCallId: part.toolCallId })}>
  Approve
</button>
```

After:

```tsx title="inertia/components/approval_buttons.tsx"
<button onClick={() => approve(part.toolCallId)}>Approve</button>
```

## `governanceAuthorize` is removed: one `dashboard.authorize` gates the console and its routes

The agent had two access options: `governanceAuthorize` (the `/agent/governance/*` routes; the console did not mount without it) and `dashboard.authorize` (the console page). There is now one, `dashboard.authorize`, and it gates both. `governanceAuthorize` is gone, with no alias. The console always mounts unless `dashboard: { enabled: false }` (or `governanceQueries: false`).

The function takes the `HttpContext` first, like every `@adonis-agora` console; the resolved actor is an optional second argument (`undefined` when the request has none). It also accepts an authorizer class or a lazy import of one, and can return `{ redirectTo: '/login' }`.

Before:

```ts title="config/agent.ts"
const isAdmin = (actor: Actor) => actor.roles?.includes('ADMIN') ?? false

export default defineConfig({
  governanceAuthorize: isAdmin,
  dashboard: { authorize: isAdmin },
})
```

After:

```ts title="config/agent.ts"
const isAdmin = (ctx: HttpContext, actor?: Actor) => actor?.roles?.includes('ADMIN') ?? false

export default defineConfig({
  dashboard: { authorize: isAdmin },
})
```

Or with `@adonis-agora/authz`:

```ts title="config/agent.ts"
import { authorizeByRoles } from '@adonis-agora/authz'

export default defineConfig({
  dashboard: { authorize: authorizeByRoles({ roles: ['ADMIN'], loginPath: '/login' }) },
})
```

What else changes:

- **No `authorize` = open outside production, `403` in production.** Before, omitting `governanceAuthorize` left the console and `/agent/governance/*` unmounted (`404`). Now both are served; outside production they are open, in production every request answers `403` and one warning is logged at boot. Set `authorize` before you deploy.
- **The actor resolver no longer gates the console by itself.** `authorize` decides, with the actor when one resolves. A hook that read `actor.roles` must read `actor?.roles`.
- **`dashboard.onUnauthenticated` is removed.** Return `{ redirectTo: '/login' }` from `authorize` instead (what `authorizeByRoles({ loginPath })` does for a signed-out visitor).
- **Denials answer `{ error }`.** `/agent/governance/*` answers `403 { "error": "forbidden" }` or `401 { "error": "unauthenticated" }` (plus `redirectTo` when `authorize` returned one) instead of `{ "message": ... }`. A non-page request to the console gets the same JSON; a page navigation still gets the access-denied page.
- **Machine access:** `authorizeByToken({ token: env.get('CONSOLE_TOKEN') })` from `@adonis-agora/agent` allows `Authorization: Bearer <token>`.
- **Cross-actor privilege** on run and thread routes (approving someone else's tool call, opening their thread) now comes from `dashboard.authorize`, as it did from `governanceAuthorize`. Without it, every actor touches only its own.
- `AgentGovernanceAuthorize` is removed; use `AgentDashboardAuthorize` (or `AgentConsoleAuthorize`). `GET /agent/approvals/mine` is unchanged.

## Peer ranges

The optional `@adonis-agora/*` peers now accept 1.x, including its release candidates, as well as the 0.x releases they accepted before:

| Peer | Range |
| --- | --- |
| `@adonis-agora/authz` | `>=0.4.2 <2.0.0 \|\| >=1.0.0-rc.0 <2.0.0` |
| `@adonis-agora/diagnostics` | `>=0.1.0 <2.0.0 \|\| >=1.0.0-rc.0 <2.0.0` |
| `@adonis-agora/durable` | `>=0.43.3 <2.0.0 \|\| >=1.0.0-rc.0 <2.0.0` |
| `@adonis-agora/media` | `>=0.18.0 <2.0.0 \|\| >=1.0.0-rc.0 <2.0.0` |
| `@adonis-agora/telescope` | `>=0.4.0 <2.0.0 \|\| >=1.0.0-rc.0 <2.0.0` |

`@adonis-agora/agent-dashboard` accepts `@adonis-agora/agent` `>=0.26.0 <2.0.0 || >=1.0.0-rc.0 <2.0.0`.

`@streamdown/code` 2 is accepted alongside 1 (`^1.1.1 || ^2.0.0`), and the `react-dom` peer is `^18.0.0 || ^19.0.0`, the same range as `react`.
