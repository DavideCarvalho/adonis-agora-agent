A dependency-light React SPA (`@adonis-agora/agent-dashboard`) that visualizes the agent's own [governance read-model](/docs/agent/governance/read-model) — spend by model and by actor, the daily usage/cost trend, recent runs, threads and tool calls, a reliability panel, an approvals inbox, and today's quota. It's a pure consumer of the agent provider's *real* routes; the provider that serves it is a thin static server, no bundled API.

## Install & mount

`node ace configure @adonis-agora/agent` already registers an **embedded** dashboard provider — the SPA is bundled straight into `@adonis-agora/agent`'s own `dist/` at build time, so there is nothing extra to install or register. It mounts at `<agentPath>/dashboard` (default `/agent/dashboard`), reading `config/agent.ts` for the agent `path` and `actorResolver`, and gates every request through the **same** actor resolver as the governance routes — an app that never configured a resolver exposes nothing.

<Callout type="info" title="Standalone install still works">
`@adonis-agora/agent-dashboard` also ships as its own installable package with its own provider, serving the identical SPA, for apps that configured it before the embedded provider existed or that want its independent release cadence:

```bash
node ace add @adonis-agora/agent-dashboard
```

```ts title="adonisrc.ts"
providers: [
  () => import('@adonis-agora/agent/agent_provider'),
  () => import('@adonis-agora/agent-dashboard'),
]
```

Both providers read the exact same `config('agent').dashboard` block below. Register only ONE of the two — mounting both at the same path throws AdonisJS's "duplicate route" error at boot.
</Callout>

<Callout type="warn" title="It mounts only when the read-model it reads does">
The console consumes `/agent/governance/*` and `/agent/quota/today`. Those governance routes exist only when the agent config carries a `governanceAuthorize` gate, so **the console refuses to mount without that gate too** — it would otherwise load and `404` on every panel but Quota. Set `governanceAuthorize` in `config/agent.ts` (e.g. an ADMIN check) to bring back the routes and the console together, or `governanceAuthorize: () => true` to deliberately restore the old behaviour of letting ANY authenticated actor read them. The provider logs a boot warning when it declines. (`pricingStore` is what fills in cost.) See [Governance read-model](/docs/agent/governance/read-model).
</Callout>

## Toggle & relocate

An optional `config('agent').dashboard` block toggles the SPA and overrides its mount path (it reuses the agent's `path` and `actorResolver`, so it stays behind the same gating):

```ts title="config/agent.ts"
export default defineConfig({
  // ...
  dashboard: { enabled: true, path: '/agent/dashboard' },
})
```

Set `enabled: false` to keep the routes off entirely.

## Reuse the browser client

The framework-free fetch client is exported for your own UI:

```ts
import { AgentClient } from '@adonis-agora/agent-dashboard/client'

const client = new AgentClient({ baseUrl: '/agent' })
const spend = await client.spendByModel({ fromDay: '2026-03-01', toDay: '2026-03-07' })
```

For a live-activity view (in-flight runs, streaming tool calls) rather than the durable history, see the [Telescope "Agent" tab](/docs/agent/governance/telescope).
