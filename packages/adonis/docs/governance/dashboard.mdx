A dependency-light React SPA over the agent's own [governance read-model](/docs/agent/governance/read-model) — spend by model and by actor, the usage trend, a filterable run list with full traces, thread drill-downs, per-tool stats, reliability, an approvals inbox, today's quota, and a model-pricing editor. It is bundled into `@adonis-agora/agent` itself and served by a thin static provider; there is no bundled API, every panel reads the same routes your own client could.

## It is already registered

`node ace add @adonis-agora/agent` registers the dashboard provider along with the agent provider, so there is nothing to install. It mounts at `<agentPath>/dashboard` — `/agent/dashboard` by default — reading `config/agent.ts` for the agent `path` and `actorResolver`.

It always mounts, unless you turn it off with `dashboard: { enabled: false }` or turn its data off with `governanceQueries: false` (the console then has nothing to show, and a boot warning says so). `governanceQueries` left *unset* is fine — it defaults to the Lucid read-model when your main store is Lucid.

## Access

One option decides who may use the console: `dashboard.authorize`. It gates the console page **and** every `/agent/governance/*` route its panels read, so the page and its data can never disagree.

```ts title="config/agent.ts"
import { defineConfig } from '@adonis-agora/agent'
import { authorizeByRoles } from '@adonis-agora/authz'

export default defineConfig({
  // ...
  dashboard: {
    authorize: authorizeByRoles({ roles: ['ADMIN'], loginPath: '/login' }),
  },
})
```

<Callout type="warn" title="Omitted: open outside production, closed in production">
Without `authorize`, the console and `/agent/governance/*` are open while the app is not in production. In production every one of those requests is refused with `403`, and the app logs once at boot:

```
[@adonis-agora/agent] console has no `authorize` configured: it is open outside production and denies every request in production. Set `authorize` in config/agent.ts.
```
</Callout>

`GET /agent/approvals/mine` is not gated by `authorize`: it always answers the calling actor's own pending approvals, so a non-admin chat can poll its own.

When `authorize` is set, an actor it allows may also act on other actors' runs and threads (approve a tool call from the Approvals inbox, open a thread). Without it, every actor can only touch its own — see [object-level ownership](/docs/agent/governance/authorization#object-level-ownership).

### The authorize contract

`authorize` is the same option every `@adonis-agora/*` console takes, in three forms. Each gets the request's `HttpContext` first and, here, the actor your `actorResolver` resolved as an optional second argument (`undefined` when the request has none):

```ts title="config/agent.ts"
import { authorizeByToken } from '@adonis-agora/agent'
import { authorizeByRoles } from '@adonis-agora/authz'
import env from '#start/env'

dashboard: {
  // An inline function
  authorize: (ctx) => ctx.auth.user?.isAdmin === true,
  authorize: (ctx, actor) => actor?.roles?.includes('ADMIN') ?? false,

  // A helper that returns one
  authorize: authorizeByRoles({ roles: ['ADMIN'], loginPath: '/login' }),
  authorize: authorizeByToken({ token: env.get('CONSOLE_TOKEN') }),

  // A class, built by the container per request (so @inject() works)
  authorize: ConsoleAccess,

  // A lazy import of that class, loaded on the first request
  authorize: () => import('#policies/console_access'),
}
```

```ts title="app/policies/console_access.ts"
import { inject } from '@adonisjs/core'
import type { HttpContext } from '@adonisjs/core/http'
import type { Actor, ConsoleAuthorizer } from '@adonis-agora/agent'
import AuditService from '#services/audit_service'

@inject()
export default class ConsoleAccess implements ConsoleAuthorizer {
  constructor(private audit: AuditService) {}

  async authorize(ctx: HttpContext, actor?: Actor) {
    if (!ctx.auth.user) return { redirectTo: '/login' }
    await this.audit.record('agent-console', ctx.auth.user.id)
    return actor?.roles?.includes('ADMIN') ?? false
  }
}
```

A class written for another `@adonis-agora` console (durable, telescope, media, payments) works here unchanged: it receives `ctx`, and can ignore the actor.

`authorizeByToken({ token })` is for machine access — a script reading `/agent/governance/*`. It allows a request carrying `Authorization: Bearer <token>` and answers `401` otherwise; it reads no query string or other header, and throws at boot when the token is empty.

| Return | Page navigation | API call (`/agent/governance/*`, assets) |
| --- | --- | --- |
| `true` / `{ allowed: true }` | allowed | allowed |
| `{ allowed: false, reason: 'unauthenticated' }` | `401` page | `401` `{ "error": "unauthenticated" }` |
| `{ allowed: false, reason: 'forbidden' }`, `{ allowed: false }`, `false` | `403` page | `403` `{ "error": "forbidden" }` |
| `{ redirectTo: '/login' }` | `302` to `/login` | `401` `{ "error": "unauthenticated", "redirectTo": "/login" }` |
| throws | `403` page | `403` `{ "error": "forbidden" }` |

A denying `{ allowed: false }` is a truthy object — the gate normalises it, so it denies; never test a hook's result with `if (!result)` yourself. If the hook answers the request itself (`ctx.response.redirect(...)`), that answer is kept.

## Configuration

The console's settings live in the same `config/agent.ts` object, under `dashboard`:

```ts title="config/agent.ts"
export default defineConfig({
  // ...
  dashboard: {
    enabled: true,
    path: '/ops/agent',
    authorize: (ctx, actor) => actor?.roles?.includes('ADMIN') ?? false,
  },
})
```

| Key | Default | Meaning |
| --- | --- | --- |
| `enabled` | `true` | `false` keeps the console off. |
| `path` | `<agentPath>/dashboard` | Where the SPA mounts. |
| `authorize` | open outside production, `403` in production | Who may use the console and `/agent/governance/*`. See [Access](#access). |
| `accessDenied` | — | Tweak or replace the [access-denied page](#the-access-denied-page) a refused browser sees. |

### The access-denied page

A refused page navigation gets a real page rather than JSON: a dark card in the console's visual language showing the status (`401` or `403`), a sentence explaining the refusal and a "Back to app" link. It carries no inline script, so a nonce'd `script-src` CSP cannot break it (its one inline `<style>` picks up `@adonisjs/shield`'s request nonce). Outside production, a thrown `authorize` message is shown on it as a developer detail.

Tweak it with `accessDenied` — every field optional:

```ts title="config/agent.ts"
dashboard: {
  accessDenied: {
    brand: 'Entre Textos',           // eyebrow + <title>; default "Agent"
    title: 'Sem acesso',             // default depends on the refusal
    message: 'Peça ao admin para liberar o console de governança.',
    homeHref: '/admin',              // "Back to app"; default "/", `false` hides it
    homeLabel: 'Voltar',
    accent: '#f59e0b',               // any CSS colour; default: the console's violet
  },
}
```

Or replace it. Pass a function and it receives the refusal (`status`, `reason` — `'unauthenticated'` or `'forbidden'` — `basePath`, `detail`, and the CSP `nonce` when there is one) plus the `HttpContext`. Return an HTML string to have it served with the right status; answer the request yourself and return nothing to make the provider stand down:

```ts title="config/agent.ts"
dashboard: {
  accessDenied: (info, ctx) => {
    if (info.reason === 'unauthenticated') {
      ctx.response.redirect(`/login?next=${encodeURIComponent(info.basePath)}`)
      return
    }
    return `<!doctype html><title>${info.status}</title><h1>Sem acesso</h1>`
  },
}
```

### Redirecting instead of returning the page

For a console a human opens in a browser, a redirect to your login page is often friendlier than any page. Return `{ redirectTo }` from `authorize` (what `authorizeByRoles({ loginPath })` does for a signed-out visitor): a page navigation is redirected there, an API call gets `401` JSON carrying the path.

```ts
dashboard: {
  authorize: (ctx) => (ctx.auth.user ? ctx.auth.user.isAdmin === true : { redirectTo: '/login' }),
}
```

<Callout type="info" title="Thrown messages are dev-only">
When `authorize` throws, the page (or the JSON `detail`) shows the error message only outside production. In production it is the generic refusal.
</Callout>

## What is in it

Nine sections, reachable by hash (`#runs`, `#approvals`, …), with a from/to day picker scoping the Overview and a light/dark toggle.

| Section | What it shows |
| --- | --- |
| **Overview** | Spend and token stats, spend by model (donut + table), spend by feature — agent turns and [recorded usage](/docs/agent/governance/quota-and-cost#recording-usage-outside-agent-turns) (transcription, TTS, direct calls) side by side, in the units each billed — the usage trend, spend by actor. |
| **Runs** | Filterable, cursor-paginated run list (status, agent, actor, date range). A row opens the full trace. |
| **Threads** | Recent threads, and a drill-down with lifetime usage, recent runs and recent messages. |
| **Tool calls** | The recent tool-call feed. |
| **Approvals** | The cross-actor HITL inbox — **and the approve/reject buttons.** |
| **Tools** | Per-tool rollup: calls, failures, rejections, mean, p50 and p95 duration. Sortable. |
| **Reliability** | Run-outcome breakdown and reliability stats, time to first token and turn duration (p50/p95), failures by code. |
| **Quota** | Today's spend for the calling actor — the one per-actor panel. |
| **Pricing** | Current per-1M model rates, **and an editor to upsert them.** |

<Callout type="warn" title="It is not a read-only console">
Two sections write. **Approvals** posts to `/agent/tool-call/approve` and `/agent/tool-call/reject`, which resumes or rejects a suspended run — a real, irreversible side effect on someone else's conversation. **Pricing** posts to `/agent/governance/pricing`, which changes what every subsequent turn costs and, because rollups are computed against current prices, what your spend reports say.

Gate it accordingly. `dashboard.authorize` is the switch, and "anyone authenticated" is not the right value for it.
</Callout>

The **run trace** (a row in Runs) is where most investigations end up: the run's summary stats, where its time went (queue / model / tools / other, then each step's model time and tool calls — see [run timings](/docs/agent/diagnostics#where-a-runs-time-goes)), its message timeline, every tool call with the pending-approval subset called out, and the usage ledger row by row — which is where you can see a `null` cost and know the model was unpriced rather than free.

**Pricing** shows its own panel rather than a generic error when the API answers `501`; that means no `pricingStore` is bound, so there is nothing to edit. See [Quota & cost](/docs/agent/governance/quota-and-cost).

## Reading the routes yourself

The console's fetch client is exported, so your own admin UI can read the same data without reimplementing the endpoints:

```ts
import { AgentClient } from '@adonis-agora/agent-dashboard/client'

const client = new AgentClient({ baseUrl: '/agent' })

const spend = await client.spendByModel({ fromDay: '2026-03-01', toDay: '2026-03-07' })
const byFeature = await client.spendByFeature({ fromDay: '2026-03-01', toDay: '2026-03-07' })
const runs = await client.listRuns({ status: 'failed', first: 50 })
const trace = await client.runDetail(runs.items[0].runId)
const thread = await client.threadDetail(trace.run.threadId)
const prices = await client.pricing()
```

Thirteen read methods and three writes (`approveToolCall`, `rejectToolCall`, `upsertPrice`). It is a plain `fetch` wrapper — no React, no state — so it works from a server-side script as readily as from a browser.

## The standalone package

`@adonis-agora/agent-dashboard` also ships as its own package with its own provider, serving the identical SPA, for apps that wired it before the bundled provider existed or that want its independent release cadence. Register it by hand:

```ts title="adonisrc.ts"
providers: [
  () => import('@adonis-agora/agent/agent_provider'),
  () => import('@adonis-agora/agent-dashboard'),
]
```

Both providers read the same `agent.dashboard` block and run the same gating logic. **Register only one** — mounting both at the same path throws AdonisJS's duplicate-route error at boot, so if you add the standalone one, drop `@adonis-agora/agent/dashboard_provider` from `adonisrc.ts` first.

<Callout type="info" title="No `node ace add` for the standalone package">
It exposes no `configure` hook, so `node ace add @adonis-agora/agent-dashboard` has nothing to run. Install it and register the provider manually as above.
</Callout>

For live in-flight activity alongside the rest of your app's instrumentation, see the [Telescope "Agent" tab](/docs/agent/governance/telescope) — and set its `runHref`/`threadHref` to `/agent/dashboard` so a Telescope panel links straight into a full trace here.
